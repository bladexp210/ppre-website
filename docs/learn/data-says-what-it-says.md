# The data says what it says

One core design rule. It applies to both builds:

- the IPIP-NEO-120 build
- the Understanding Society build

We don't make the data say what it doesn't say. If the data has an answer, we say the answer as it is, in plain English using imagery and text. If we don't have an answer, we just say the data doesn't have an answer for that. This includes the specific case where groups overlap almost completely: that is an answer in itself, telling the reader there is functionally no group distinction and that variability among in-group members is more important than the differences between the groups.
